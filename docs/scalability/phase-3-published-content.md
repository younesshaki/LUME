## Shared implementation and route ownership

`apps/web` renders `/` (plus legacy `/home`), `/contact`, `/products`, `/products/[productId]`, and one-level published service/custom slugs. The Phase 2 inventory/detail and three compatible public vehicle read transports retain their ownership and UUID URLs. Missing services/custom publications return 404; they are never invented or redirected to home.

The original React renderers lived in root `src`, while `@lume/blocks` held schema/descriptors. The approved extraction moves reusable views, pure helpers and interactive leaves to `packages/blocks/src/react`. Original Vite files retain context, transports, navigation, sound and visitor adapters and import those same implementations. This is a shared extraction, not a second block implementation. The original CSS, public artwork/catalog and shader ownership remain in place; Next references permitted public styles/data/assets. Vite config, root build/deploy scripts, root API functions and admin source are unchanged. The lockfile adds only web PostCSS support at the existing Tailwind version.

`ServerBlocks` uses the existing schema, descriptor registry, visibility and appearance resolver. All 34 standard-mode descriptors have explicit adapters. Text, headings, galleries, business content, product/showcase cards and vehicle data render server-side through shared views. Stateful filters/forms/consent/quick search and interactive announcement/FAQ leaves hydrate independently. Shared views accept thin environment adapters rather than importing root application contexts. Server imports and transitive shared-package client imports are checked during web build/typecheck; server-only loaders cannot pull browser modules, and client graphs cannot reach server/config, Node APIs, DB/admin or environment access.

Product and vehicle navigation uses native URLs. FAQ uses native details and numeric trust values are visible in initial HTML. Chat, canvas/viewer and cinematic entry/navigation are not required to read the page. The preview intentionally uses a small noindex footer instead of transferring full Vite chrome/visitor behavior. Those later owners have not been migrated. Forms remain client islands: their content renders, with an explicit noscript instruction to enable JavaScript for submission.

## Published states, SEO and failure behavior

The server uses anonymous `tenant_by_slug`, `get_tenant_theme`, `list_published_nav_pages` and `get_published_page`. Every page read carries the verified tenant ID; the RPC selects `published_revision_id`. There are no draft-table application queries or caller-selected revisions. Request-local React caching shares one document between metadata and content; database fetches and HTML/Flight are no-store across requests.

| Case                                         | Behavior                                                                                                                                                                                                    |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Valid published document                     | Shared views, public revision marker, exactly one page h1                                                                                                                                                   |
| Missing reserved home/contact/products       | Original shared defaults; Glo3D home uses the extracted original template fallback                                                                                                                          |
| Empty reserved document                      | Explicit `empty` state with the original built-in fallback policy; never a draft                                                                                                                            |
| Empty custom/services publication            | Published title/h1 and explicit empty message                                                                                                                                                               |
| Missing custom/services publication          | HTTP 404                                                                                                                                                                                                    |
| Invalid document / public content outage     | Failure-only HTTP 307 to `/preview/unavailable`, followed by a complete **HTTP 503 HTML document** with title/description/canonical/noindex, one h1 and native retry link; no script or JavaScript required |
| Draft/revision/public preview-token selector | HTTP 404                                                                                                                                                                                                    |

The error document escapes tenant content, rejects external/malformed retry paths and does not expose private upstream details. A streaming Suspense fallback is deliberately absent: it produced an extra raw h1 on valid documents. Successful routes do not take the error redirect.

Next alone emits route metadata using the existing pure SEO resolver: title, description, verified canonical, Open Graph and noindex. Template/theme/draft/tracking selectors do not appear in canonicals; `/home` canonicals to `/`. Product detail respects the published grid's categories. The existing database RPC exposes page-level SEO alongside revision-scoped blocks: **SEO itself is not versioned per block revision today**. Body draft isolation is proven; this phase preserves that contract and makes no stronger claim about historical/versioned SEO. No schema change is made.

## Staging forms, consent and origin configuration

The shared form leaves retain validation, success/error states and Turnstile behavior. The Next same-origin proxy preserves the real Origin and the existing tenant/body/first-touch attribution contract. ## Visual method, provenance and data limits

Staging has **one** active tenant, `demo`, with real home/contact/products publications and Luxury selected. Both templates and light/dark use presentation overrides on the same identity. No second tenant, remote page or template was fabricated. Services and `our-story` in local renderer/state tests are labelled published-RPC fixtures because neither exists in staging. Hosted requests to those absent publications return 404. Validation of real authored service/custom content remains a future data-availability check, not a claim made by these fixtures.

The live-app parity proof compares production builds of the Vite application before and after extraction, using identical frozen public staging reads rather than redeploying customer domains. It includes the original full chrome, top/bottom captures, vehicle gallery/inquiry dialogs, product filtering/detail/back, contact success contract and consent persistence. It retains the verified live page-renderer flag (unset/false). A separate CMS-on comparison covers published block rendering in old Vite, shared Vite and Next.

All 40 raw viewport comparisons pass Playwright's perceptual comparator (threshold 0.1, zero allowed differing pixels, no masks); 28 are byte-identical PNGs. The other 12 have only 6–40 differing RGB pixels out of 1,152,000, with maximum channel delta 1–2. Raw counts and hashes are committed. JPEG review copies are encoded after comparison. Equal vehicle-response order controls the existing Vite competing title effects; those effects are unchanged. Public images are frozen equally, visible images decoded, fonts awaited, pointer neutral and scroll instant. This proves the requested matrix, not every browser/GPU, content configuration or later cinematic feature.

Next's published-content captures compare full main content after sampling text/styles/geometry; global Next chrome is outside this phase. Intentional Next preview differences are the noindex footer/native links, progressive FAQ/visible counters and server outage document. **No intentional Vite visual/behavioral differences.** Unmocked hosted JS-off mobile and R2 response evidence complement the deterministic screenshot fixtures.

The foundation tests simulate two active tenants and alternate HTML/Flight plus 20 concurrent requests. Vehicle tests run 36 HTML/Flight/API alternating/concurrent requests, with a known foreign active tenant denied a vehicle UUID. Content tests add 24 concurrent public/unknown requests. Hosted unknown/forged selectors and an actual unapproved host reject. Injected `x-forwarded-host` is normalized by Vercel; a 200 with unchanged verified canonical is the previously accepted anti-spoofing proof, not a claimed literal rejection of the normalized request.
