# Storyboard: How Git Works

## Structure
- Style: manga + neutral
- Layout: standard
- Aspect ratio: 3:4 (portrait)
- Pages: 1 cover + 5 content pages
- Language: English
- Characters: Dev (protagonist), Git Mascot

---

### Cover — "How Git Works"
- **Panel 1** (full page): Dev sits at a desk with laptop, looking overwhelmed by scattered papers. Git Mascot floats beside them holding a "Git" flag.
- **Text**: "How Git Works — A Developer's Guide to Version Control"
- **Purpose**: Hook the reader, establish characters

---

### Page 1 — "The Problem"
- **Panel 1**: Dev saves files with names like `report_final_v3_actually_final.py` — messy desktop.
- **Panel 2**: Git Mascot appears, says "There's a better way."
- **Panel 3**: Git Mascot opens a magical door showing a timeline of snapshots (commits).
- **Purpose**: Show the problem Git solves — version tracking

---

### Page 2 — "Snapshots: Repositories & Commits"
- **Panel 1**: Git Mascot shows a "snapshot camera" — each click creates a commit.
- **Panel 2**: Dev clicks — a commit box appears with a hash (a1b2c3d). The working directory is shown as a room where they edit code.
- **Panel 3**: Multiple commit boxes in a chain (timeline). Git Mascot explains: "Each commit is a full snapshot, not just the differences."
- **Purpose**: Explain commits as snapshots in the repository timeline

---

### Page 3 — "The Three Trees"
- **Panel 1**: Three labeled rooms: Working Directory (messy desk), Staging Area (organized table), Repository (library shelves).
- **Panel 2**: Dev writes code at the Working Directory desk. Git Mascot says "git add" — changes float to the Staging Area table.
- **Panel 3**: Dev says "git commit" — the staged items fly to the Repository library shelves and get a label (commit hash).
- **Purpose**: Explain the three-tree architecture (working dir → staging → repo)

---

### Page 4 — "Branching Out"
- **Panel 1**: Main timeline (main branch) stretching left to right. Git Mascot shows a fork in the road.
- **Panel 2**: Dev walks down a new path (feature branch) — "git branch feature-x". The path diverges from main.
- **Panel 3**: Both branches grow in parallel. Dev works on feature while main path continues with different commits.
- **Purpose**: Explain branches as parallel timelines

---

### Page 5 — "Bringing It Together: Merge"
- **Panel 1**: Dev's feature path needs to rejoin main. Git Mascot holds two ends of a rope.
- **Panel 2**: "git merge" — the two paths smoothly merge into one. Confetti. "Fast-forward merge!"
- **Panel 3** (optional): A second scenario where the paths don't align — "CONFLICT!" — Dev and Git Mascot work together to resolve by editing a file.
- **Panel 4**: Final panel — Dev and Git Mascot high-five. Dev says "I get Git now!"
- **Purpose**: Explain merging and conflict resolution. Happy ending.

---

## Visual Style Notes
- Clean manga style, mostly white/light backgrounds
- Warm orange/gold accents (Git brand colors)
- Simple panel layouts — 2-3 panels per page for clarity
- Characters use expressive body language, minimal text in bubbles
- The Git Mascot should be a small orange/red floating cube with a smiley face
